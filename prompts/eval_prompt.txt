## Evaluation Criteria:

### Tool Invocation Assessment:
1. **Tool Selection**: Did the agent choose the most appropriate tool(s) for the user's query?
2. **Parameter Accuracy**: Were the input parameters correct, complete, and properly formatted?
3. **Tool Sequence**: If multiple tools were used, was the sequence logical and necessary?


#### CRITICAL — Conversation-Aware Tool Redundancy Exception:
Before penalizing tool selection, inspect the full conversation history. If a direct tool or SOP path was already successfully executed in a prior turn for the same underlying data need (e.g., club details, class listings, club IDs), and the current turn's query is a derivative or follow-up of that prior result, the agent is NOT required to re-invoke those tools.

In such cases, defaulting to `retriever_tool` is the correct and expected behavior under the Zero-Knowledge Policy — the agent must ground its response in an authorized source, and retriever is the appropriate fallback when prior tool results do not directly answer the current refinement.

Do NOT penalize tool_selection or tool_sequence in these cases. Evaluate only whether:
- The retriever call was a reasonable grounding attempt given what was missing
- The agent correctly used conversation-established data (e.g., club IDs, location) without re-fetching it unnecessarily

**Do NOT penalize the knowledge/retriever tool choice in this scenario.** Calling the knowledge tool as a valid fallback is correct behavior. Only penalize it when a more specific available tool clearly should have been used instead, and the agent had sufficient context to use it.

### SOP Invocation Assessment:

#### CRITICAL — Distinguish Carried-Over History from Active Execution:
The agent's `<sop-tracking>` block may contain entries from **previous turns** that are carried forward for continuity. This is expected and correct behavior. You must **not** treat prior-turn SOP entries as evidence that an SOP was triggered or executed in the **current turn**.

To determine whether an SOP was actually triggered this turn:
- Look for a **new `<sop_execution>` block with `IN_PROGRESS` or a newly initiated status**, not one already marked `COMPLETED` from a prior turn.
- Confirm that the tools listed under `<tools_used>` in that entry were **actually invoked in this turn's intermediate steps**, not just referenced from earlier steps.
- If the only SOP entries visible are `COMPLETED` and match prior turns without new tool invocations, treat the current turn as having **no active SOP execution**.

#### Scoring:
1. **Correct SOP Identification**: Did the agent accurately recognize and trigger the appropriate SOP based on the current turn's query and its trigger conditions?
2. **Step and Tool Compliance**: Did the agent follow the SOP's defined action flow in the right order, using all required tools with correct parameters?
3. **Continuity and Constraints**: Did the agent maintain context across turns, handle conditional logic properly, and comply with all SOP-specific rules?

**Important**: If no SOP was required for the current turn's query and none was triggered, this is **correct behavior and should receive high scores**. Do not penalize the agent for not triggering an SOP when the query does not warrant one.

### Custom Tone Assessment:
Check if the response follows only the rules explicitly written in the Custom Tone Instructions. Do not penalize anything unless it directly violates a specific stated rule. If emojis, exclamation points, or casual language aren't explicitly forbidden in the instructions, they cannot reduce the score. Only evaluate what is literally required or prohibited — add no interpretations of your own.

---

### Response Quality Assessment:
1. **Query Fulfillment**: Does the response completely address what the user asked for?
2. **Accuracy**: Is all information in the response supported by the tool outputs? Does it correctly adhere to the XML format?
3. **Hallucination Detection**: Does the response contain any information not present in the tool outputs or conversation history?
4. **Completeness**: Is the response thorough and complete?

#### CRITICAL — Conversation-Grounded Claims Are Not Hallucinations:
If the agent's response references facts (club names, addresses, class times, club IDs) that were established by tool outputs in **prior turns of the same conversation**, these are valid authorized sources under the Zero-Knowledge Policy and must NOT be flagged as hallucinations. Only flag content that is absent from both current tool outputs AND the conversation history.

#### CRITICAL — Reasoning Block vs. Response Content:
When checking for hallucinations, evaluate the **visible response content** (text bubbles, cards, buttons, etc.) — not the `<reasoning>` or `<sop-tracking>` blocks. Carried-over SOP history in the reasoning block is a structural convention, not a factual claim made to the user, and must not be flagged as hallucination.

#### NOTE — Unresolvable Follow-ups:
If the current query is a follow-up that cannot be resolved because the required data point (e.g., a "6 PM class" that never appeared in any prior tool output or conversation turn) was never established in the conversation, an `unclassified` outcome with a retriever attempt is the correct handling. Do not penalize query fulfillment for failing to answer what was structurally unanswerable given the conversation state.

---

### Adjust Response Assessment:
1. **Rule Identification Accuracy**: Did the agent correctly recognize which adjust response rule(s) applied to the user’s query and trigger them appropriately?
2. **Instruction Compliance**: Did the response fully follow the rule’s instructions, including required phrasing, hyperlinks, and disallowed actions?
3. **Completeness and Precision**: Did the response include all mandatory elements (e.g., advisor connection phrase, link placement, contact guidance) and exclude prohibited content (e.g., personal names, missing links, or incomplete instructions)?

- Compare the agent's tool inputs against the tool schemas to verify correctness
- Check if the agent followed tool descriptions and constraints (e.g., "ALWAYS use carousel", "max 3 clubs"). FYI Tool outputs are truncated so thay shouldn't be penalised.
- Consider if alternative tools might have been more appropriate

### Scoring Guidelines:
- 10: Perfect execution with no issues
- 8-9: Minor issues that don't significantly impact results
- 6-7: Moderate issues that partially compromise effectiveness
- 4-5: Significant issues that substantially impact results
- 1-3: Major failures in execution
